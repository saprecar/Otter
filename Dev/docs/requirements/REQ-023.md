# REQ-023: Zero-Install Browser Web Streaming Architecture & Specification

## 1. Scope & Device Coverage
Defines the technical architecture, bare-minimum user interface, orientation protection, platform limitations, and security model for running Otter via mobile web browsers without installing native applications or requiring paid developer accounts:
- **Apple Devices**: iPhone and iPad running Safari (iOS & iPadOS 11+).
- **Android Devices**: Android Phones and Android Tablets running Google Chrome, Brave, or Firefox.

---

## 2. Bare-Minimum Mobile Web UI Specification & Orientation Lock

### A. Locked Portrait Mode UI Enforcement
To maintain parity with the native app's locked portrait experience and prevent UI layout breakage:
- **Strict Portrait Lock**: The web UI is strictly locked in portrait orientation across all phones and tablets.
- **Landscape Rotation Protection**: If the user physically rotates their device (iPhone, iPad, or Android tablet) into landscape orientation, the UI does **NOT** flip into a distorted landscape layout. Instead, a CSS orientation guard (`@media (orientation: landscape)`) maintains portrait layout dimensions, ensuring all controls, buttons, and the camera viewfinder stay perfectly upright and accessible.

### B. Minimal Web UI Layout
Because mobile web browsers operate inside restrictive sandbox environments, the web streamer UI is strictly limited to essential controls:

```text
+-------------------------------------------------------------+
|  Otter Web Streamer                                         |
|  [Status Badge: ● Disconnected / ● Live 30 FPS]             |
+-------------------------------------------------------------+
|                                                             |
|                                                             |
|                 Live HTML5 Camera Viewfinder                |
|                    (<video id="preview">)                   |
|                                                             |
|                                                             |
+-------------------------------------------------------------+
|  Connection: 192.168.1.50:8089 | Mode: Wi-Fi LAN (WebRTC)   |
|  Device: iPhone / iPad / Android Phone / Tablet (Portrait)  |
+-------------------------------------------------------------+
|  [ Start Stream ]       [ Pause ]        [ Stop ]           |
+-------------------------------------------------------------+
|  [ Flip Lens: Front / Rear ]   [ Resolution: 720p / 1080p ] |
+-------------------------------------------------------------+
|  WARNING: Keep this tab open. Minimizing pauses stream.     |
+-------------------------------------------------------------+
```

### Supported Web Controls:
1. **Live Viewfinder**: Full-bleed responsive `<video>` element with zero letterboxing.
2. **Start / Pause / Stop**: Initializes WebRTC peer connection, pauses media tracks, or shuts down camera hardware.
3. **Flip Lens**: Toggles between front (`user`) and back (`environment`) camera devices via `facingMode`.
4. **Resolution Selector**: Toggles between 720p (1280x720) and 1080p (1920x1080) stream constraints.
5. **Connection & Device Status**: Displays active local IP, port, connection type, and detected phone/tablet profile.

## 3. Standardized Device Profiling (iOS vs Android)

### A. Apple iOS Standardized Sensor Profiles
Apple iPhone hardware uses standardized, predictable camera sensors. Based on the browser `navigator.userAgent` and screen resolution, the system accurately displays the known physical optics:
- **iPhone Standard / Pro (13-16 series)**: 12MP / 48MP main sensor (f/1.5-f/1.78), 12MP Ultra-Wide, 12MP TrueDepth Front.
- **Hardware Limitations**: HTML5 Safari only exposes the synthesized logical camera stream; it does NOT allow raw multi-lens switching (telephoto vs wide) unless exposed as distinct `MediaDeviceInfo` entries.

### B. Android Browser Fallback
Android devices have thousands of fragmented camera HALs. In Chrome web mode, the browser only exposes generic `videoinput` devices without access to proprietary OEM quad-bayer remosaic, manual shutter speed, or ISO registers.

## 5. Security Model, Risk Analysis & User Warnings

### A. Self-Signed HTTPS Certificate Requirement
- **Requirement**: Modern mobile browsers (Safari on iOS and Chrome on Android) strictly require a secure context (`HTTPS`) to grant camera access (`navigator.mediaDevices.getUserMedia`). Non-HTTPS calls on local IPs are rejected.
- **Solution**: The Otter Desktop server automatically generates an ephemeral, local self-signed TLS certificate.
- **User Warning**: When opening `https://<PC-IP>:8089` for the first time, Safari/Chrome will display a "Certificate Not Trusted" warning. Users must tap **Advanced -> Proceed / Continue to site**. This is standard for local P2P networks with no public domain name.

### B. Network Isolation & Security
- The web stream runs strictly on the user's private local network (LAN / Wi-Fi).
- Zero data is relayed to outside servers, public STUN/TURN relays, or third-party clouds.
- Only devices connected to the same local Wi-Fi router can access the streaming endpoint.

### C. Desktop Client Remote Control Warning
- In the Otter Desktop Client, when a device is connected via **Web Mode**, all Pro manual sliders (ISO, Shutter Speed, Focus Distance, EV Steppers, Torch Strength, Ultra Photo) are automatically disabled and grayed out with a badge indicating:  
  `[Web Mode Active: Manual Hardware Controls Not Supported by Browser Sandbox]`.
